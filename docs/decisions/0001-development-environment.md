# 0001. Python 개발 환경과 프로젝트 구조

## 상태

제안 — 기본 실행 검증 후 채택 여부 확정

## 해결할 문제

반도체 기술 문서 기반 RAG 서비스를 개발하기 위해
Python 실행 환경과 라이브러리 관리 방식을 정해야 한다.

개발 환경을 다시 구성할 수 있어야 하며,
사용하는 라이브러리 버전과 코드 위치를 명확하게 관리해야 한다.

## 검토한 대안

| 항목 | 대안 |
| --- | --- |
| 개발 언어 | Python, Java |
| 환경·의존성 관리 | venv + pip, uv |
| 코드 배치 | 프로젝트 최상위에 배치, src 폴더에 배치 |

## 선택한 방법과 이유

### 1. Python 사용

PDF 처리, 임베딩, 검색, 언어 모델 관련 도구를 활용하기 위해
Python으로 개발한다.

### 2. Python 3.12로 시작

실행 기준 버전을 명확하게 하기 위해 Python 3.12로 시작한다.

실제로 사용할 PDF 처리·검색·모델 라이브러리의 호환성은
각 도구를 도입할 때 확인한다.

지원 버전 조건은 pyproject.toml에,
개발 환경의 기본 버전은 .python-version에 기록한다.

### 3. uv로 환경과 의존성 관리

프로젝트 설정과 라이브러리 버전을 함께 관리하기 위해 uv를 사용한다.

- pyproject.toml에 프로젝트 정보와 필요한 라이브러리를 선언한다.
- uv.lock에 선택된 의존성 버전을 기록한다.
- .venv에 프로젝트 실행 환경을 구성한다.
- uv sync --locked로 잠금 파일에 맞춰 환경을 구성한다.

### 4. src 구조 사용

실제 프로그램 코드를 src/semiconductor_rag 아래에 배치한다.

문서, 평가 데이터, 설정 파일과 프로그램 코드를 구분하고,
패키지를 설치해서 사용하는 구조를 명확하게 한다.

### 5. Hatchling으로 패키지 빌드

src 아래의 semiconductor_rag 패키지를
프로젝트 실행 환경에 설치할 수 있도록 Hatchling을 사용한다.

빌드 설정은 pyproject.toml의 build-system과
tool.hatch.build.targets.wheel에 기록한다.

### 6. Ruff로 코드 검사

기본적인 코드 문제와 포맷을 일관되게 확인하기 위해 Ruff를 사용한다.

실행 명령어는 README에 기록한다.

## 예상되는 단점과 제약

- 개발 환경에 uv 설치가 필요하다.
- Python 버전을 제한했으므로 다른 버전은 별도 검증이 필요하다.
- 잠금 파일이 있어도 운영체제·하드웨어 차이까지 같아지는 것은 아니다.
- GPU 관련 라이브러리는 추가 환경 설정이 필요할 수 있다.
- 라이브러리 호환성에 문제가 생기면 버전과 선택 도구를 재검토한다.

## 검증 방법

아래 항목은 실제로 확인한 뒤 체크한다.

- [ ] uv sync --locked로 환경 설치에 성공한다.
- [ ] uv run python -m semiconductor_rag로 기본 실행에 성공한다.
- [ ] uv run ruff check . 검사를 통과한다.
- [ ] uv run ruff format --check . 검사를 통과한다.
- [ ] 별도 폴더에 저장소를 복제해 설치와 실행을 재현한다.
- [ ] .venv와 실제 비밀키가 Git 추적 대상에서 제외되어 있다.
