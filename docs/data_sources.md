# 📚 데이터 소스 선정 및 관리 기준

기준일: **2026-11-03**. 반도체 메모리·CXL·LLM 추론 문서에서 질문에 맞는 근거를 찾아 답하는 RAG 프로젝트의 입력 자료를 관리한다. 기업의 공식 서비스나 제휴 프로젝트를 의미하지 않는다.

## 현재 목록

| 구분 | 등록 수 | 현재 상태 |
| --- | ---: | --- |
| 외부 공식 자료 후보 | 7 | 정상 PDF 5건 확보, 2건 다운로드 실패 |
| 직접 작성한 예제 문서 | 5 | 로컬 개발 입력으로 선정; 사양 두 버전 포함 |
| 합계 | 12 | 등록 목록은 실행 가능한 입력 목록과 구분 |

정상 PDF 5건은 총 64쪽이다. 헤더·페이지 트리·파일 해시 확인을 마쳤으며, 모든 표·그림·읽기 순서가 검증된 상태는 아니다. 외부 자료의 재이용 허가도 확보하지 않았다. 현재 시작용 입력은 직접 작성 예제 5건이다.

기준 목록은 [data/manifests/sources.csv](../data/manifests/sources.csv)다. 앞서 생성한 `official_candidates_2026-11-03.*`는 수집 당시 기록으로 보존하고, 후속 선정·권리 상태는 `sources.csv`에서 관리한다.

## 선정 기준

| 기준 | 확인 방법 | 선정 또는 보류 기준 |
| --- | --- | --- |
| 출처 | 제조사·표준화 단체·공식 학회 배포처 확인 | 공식 배포본 우선. 재게시본과 출처 불명 자료는 보류 |
| 주제 적합성 | 메모리 용량·대역폭·지연, CXL, KV 캐시, 추론 조건과 연결되는지 확인 | 실제 질문과 근거 구절을 만들 수 있어야 함 |
| 권리와 이용 조건 | 문서 내부 표시, 배포처 약관, 문서별 허가 확인 | 다운로드 가능 여부와 색인·전송·공개 가능 여부를 각각 기록 |
| 식별 가능성 | 문서 ID, 제목, 배포처, 날짜, 버전, SHA-256 확인 | 미확인 날짜는 빈 값 또는 정밀도가 맞는 연/월로 기록. URL 폴더 날짜를 발행일로 단정하지 않음 |
| 추출 품질 | 텍스트 존재, 표와 단위, 읽기 순서, 쪽수 매핑 확인 | 깨진 표·스캔·복구된 PDF는 추가 QA 전 보류 |
| 실험 다양성 | 버전 차이, 비슷한 제품 코드, 수치 표, 한영 문서, 근거 부족 질문 | 예제 문서에서 먼저 확인하고 실제 자료로 확장 |
| 재현성 | 파일 해시, 수집 날짜, 실패 사유, 변경 기록 유지 | 같은 제목이어도 내용이 바뀌면 별도 버전으로 취급 |

제외 또는 보류 대상: 비공개/로그인 제한 자료, 접근 제한을 우회해야 하는 자료, 이용 범위 미확인 자료, 출처 없는 수치, 실제 제품으로 오인할 수 있는 가상 자료, 정답 파일이 섞인 검색 입력.

## 목록의 주요 열

| 열 | 의미 |
| --- | --- |
| document_id | 고유하고 안정적인 식별자. 파일명과 분리 |
| title / organization / document_type / language / topics | 검색·분류를 위한 기본 정보 |
| publication_date / date_note / version | 날짜 정밀도와 버전 근거. 가상 예제 생성일과 실제 문서 발행일을 혼동하지 않음 |
| source_url / download_url / local_path | 출처·배포 파일 URL·저장소 기준 상대 경로 |
| local_file_exists / pdf_pages / sha256 | 실제 파일 존재, PDF 쪽수, 전체 파일의 SHA-256. Markdown에는 PDF 쪽수를 만들지 않음 |
| download_status / selection_status / selection_reason | 확보 여부와 입력 선정 여부를 독립 관리 |
| license_status / terms_url / rights_evidence_location / rights_summary | 권리 상태, 확인한 URL과 파일 내부 위치, 확인 결과 |
| rights_reviewed_on / rights_review_status | 검토일과 검토 범위. 검토 완료가 허가 확보를 뜻하지 않음 |
| local_indexing_status / external_upload_status / redistribution_status / public_demo_status | 처리 단계별 상태를 구분. CSV 기록만으로 실행을 제어하지 않음 |
| notes | 남은 품질 검토, 실패 원인, 해석상 주의점 |

파일은 UTF-8 BOM이 있는 CSV다. 쉼표와 따옴표는 표준 CSV 규칙으로 처리했다. 한 셀 안의 복수 주제/URL은 세미콜론으로 구분한다.

## 상태 규칙

- `selected_synthetic_fixture`: 이 프로젝트에서 직접 작성하여 시작용 입력으로 선정.
- `deferred_rights_review`: 파일은 있으나 재이용 권한 확인 전 보류.
- `deferred_download_failed`: 정상 파일을 확보하지 못하여 보류.
- `hold_pending_permission`: 해당 처리에 대한 허가 범위 확인 전 보류.
- `project_fixture`: 자체 예제에 대해 예정된 로컬 개발 용도. 실제 색인 완료를 의미하지 않음.
- `not_sent`: 외부 서비스로 전송하지 않음. 전송 허가가 있다는 뜻이 아님.
- `project_license_not_selected`: 자체 예제에 대한 공개 라이선스를 이번 작업에서 새로 지정하지 않음.

실제 수집기가 만들어지면 `selected_synthetic_fixture` 문서만 명시적으로 읽는 방식부터 시작한다. CSV와 디렉터리가 존재한다는 사실만으로 접근 제어·필터링이 구현된 것은 아니다.

## 실행 입력과 확인 질문 분리

검색 대상은 [예제 README](../data/examples/README.md)에 열거한 Markdown 5개다. `example_questions.jsonl`, 예제 README, 이 기준 문서, 이용 조건 검토 문서는 검색·임베딩 입력에서 제외한다. 확인 질문의 예상 답변이 검색되는 것을 막기 위한 구분이다.

예제 질문은 12개이며 버전 지정, 최신 버전, 제품 코드 구분, 수치 계산, 정책 경계값, 한영 검색, 답변 보류를 다룬다. 개발 중 확인용이며 실제 성능이나 기업 제품에 대한 사실을 증명하지 않는다.

## 자료 추가 절차

1. 공식 배포처와 주제를 확인하고 중복 ID·해시 여부를 확인한다.
2. 원문을 확보하면 파일 헤더·실제 형식·페이지 수·SHA-256을 확인한다. 실패한 다운로드도 실패 사유를 남긴다.
3. 이용 조건과 예정된 처리 범위를 [검토 문서](data_usage_review.md)에 기록한다. 미확인 상태를 허용으로 해석하지 않는다.
4. `sources.csv`에 메타데이터·처리 상태·검토 날짜를 추가한다.
5. 권리 조건이 충족된 자료만 파싱 QA를 거쳐 별도 입력 목록에 선정한다.
6. 원문·변환 텍스트·인덱스의 공개 범위를 확인한 후 공유한다. 데이터와 정책이 바뀌면 목록·문서·평가 입력을 함께 갱신한다.

## 알려진 제한

Hot Chips PDF는 페이지 트리를 읽을 때 교차 참조 오프셋 복구가 발생했다. 렌더링과 읽기 순서 검증이 추가로 필요하다. FMS와 Micron 후보는 정상 원문이 없어 제목·발행일·권리 검토에 미확인 항목이 있다. CXL 2.0과 3.0 백서는 서로 다른 세대 자료이며 동일 문서의 단순 개정판으로 처리하지 않는다.
