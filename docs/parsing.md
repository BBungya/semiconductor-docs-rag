# 문서 파싱

문서 수집(#3)의 등록 기록을 읽어 각 문서의 현재 정상 버전을 처리합니다. 파싱 결과와 원문 위치는 청킹(#5)의 입력으로 사용합니다.

## 실행

프로젝트 루트에서 실행합니다. 등록 기록이 없는 환경에서는 수집 명령을 먼저 실행합니다.

```powershell
uv sync --locked
uv run --locked python -X utf8 -m semiconductor_rag.ingestion
uv run --locked python -X utf8 -m semiconductor_rag.parsing
```

특정 문서만 처리하려면 `--document-id example-memory-spec-v1-1`을 추가합니다. 다른 프로젝트 루트를 지정하려면 `--project-root`에 경로를 전달합니다.

## 저장 형식

결과는 프로젝트 루트의 `data/processed/<document_id>/<source_sha256>/`에 저장합니다.

| 파일 | 내용 |
| --- | --- |
| `blocks.jsonl` | UTF-8 JSON 한 줄에 블록 하나. 제목, 본문 또는 열 제목과 행으로 구성된 표 |
| `parsing_report.json` | 파서 버전, 원본 정보, 블록 개수, PDF 페이지 수, 상태, 문제 목록, 블록 파일 해시 |

PDF 블록에는 실제 페이지 순서 기준의 1부터 시작하는 페이지 번호를 기록합니다. Markdown 블록에는 제목 경로와 양 끝을 포함한 원본 줄 번호를 기록합니다. 문서 ID, 출처 버전, 원본 해시는 각 블록에 포함됩니다.

같은 문서·해시를 재처리하면 그 경로에 이번 실행의 결과를 저장합니다. 원본 내용이 바뀌면 새 해시 아래에 저장합니다. 결과를 읽을 때는 보고서의 `blocks_sha256`과 블록 파일의 실제 해시를 비교해 두 파일이 같은 결과인지 확인할 수 있습니다.

## 상태와 종료 코드

| 상태 | 의미 |
| --- | --- |
| `parsed` | 블록을 추출했고 기록된 문제가 없음 |
| `needs_review` | OCR 대상 페이지, 구조가 불확실한 표 또는 추출할 블록이 없는 등 검토할 문제가 있음. 추출한 블록은 저장 |
| `failed` | 원본 누락, 해시 불일치, 파서 오류 등으로 문서를 처리할 수 없음. 실패 이유와 빈 블록 파일을 저장 |

대상 문서가 모두 `parsed`이면 종료 코드 0, 검토 필요나 실패가 있으면 1입니다. 등록 기록을 읽지 못하거나 지정 문서가 없는 등 전체 실행 오류는 2입니다.

## 지원 범위

- Markdown은 제목·문단·목록·표와 원본 위치를 지원합니다. 파일 처음의 YAML 메타데이터는 본문에서 제외합니다.
- PDF는 페이지별 텍스트와 격자선이 있는 표를 추출합니다. 병합 셀, 선 없는 표, 복잡한 페이지의 읽기 순서, 표 제목·각주 연결은 검증 범위가 제한됩니다. 본문 블록에도 표의 글자가 포함될 수 있습니다.
- 추출 가능한 텍스트가 비어 있고 이미지가 있으면 `ocr_required`로 기록합니다. 이 상태는 OCR 후보를 나타내며 이미지 속 글자를 읽는 처리는 별도로 필요합니다.
